# Security and sensitive data

Do not post session cookies, authorization headers, Keychain exports, container backups, signing material, or device identifiers in public issues or PRs.

For a suspected vulnerability involving private data, contact the maintainer privately through a method listed on their GitHub profile. Use GitHub private vulnerability reporting if enabled. No dedicated response-time guarantee or supported-release policy is currently offered.

Identify the commit and provide a minimal reproduction using dummy data. Revoke exposed credentials with their issuing service. Removing them from the latest version does not remove them from history.

See [privacy](docs/privacy.md) and the [publication checklist](docs/publication.md).
